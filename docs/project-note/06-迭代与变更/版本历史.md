# 版本历史

## 版本号体系

**本项目不用 semver**：标签形如 `v2026.9.26.711` = 上海日期 + 时不补零 + 分两位（`AGENTS.md:5-9`）。与上游 `1.x` 完全脱钩。

| 事实 | 值 |
|---|---|
| 标签总数 | 92 |
| 最早标签日期 | 2026-09-12（仓库首个提交同日） |
| 最新标签 | `v2026.10.21.1006` |
| 提交总数 | 488 |
| 活跃提交日 | 42 天（2026-09-12 → 2026-10-24） |
| 单日最多提交 | 61（2026-10-18） |

历史遗留：`.git/packed-refs` 里仍能看到 `v1.2.0`–`v1.11.6` 的旧 semver 标签（2026-09 之前）。**不要再打这种标签**（`AGENTS.md:10`）。

面板显示的版本来自 `appVersion`：本地构建 `dev`，CI 用 `-X main.appVersion=${VERSION}` 注入（`cmd/server/main.go:40-42`、`.github/workflows/binaries.yml:56`）。

## 上游同步策略

| 项 | 说明 |
|---|---|
| 同步节奏 | 不定期（`feat: 同步上游 <range>` 类提交）；README 有「与上游的差异 / 同步上游 / 未做待办」三节 |
| 同步范围 | 以基础设施与协议对齐为主（UA/头族/脱敏规则/登录码表），业务功能自研 |
| 冲突处理 | 上游实现优先于本仓旧实现时整体替换（如品牌词整句规则移入 identity 作用域，`ce84313`） |
| 版本号 | **不与上游对齐**（本仓用日期标签） |
