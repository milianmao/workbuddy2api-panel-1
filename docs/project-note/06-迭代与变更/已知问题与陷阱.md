# 已知问题与陷阱

每条都来自代码注释里的实测记录或事故复盘。**新写代码时先扫一遍这张表**，这些问题都已经被踩过一次。

## P1 · 惊群集中单号（选号）

**现象**：并发请求全打到同一个账号。

**两个根因**（`internal/pool/pick.go:158-196` 注释）：
1. top5 截断按字典序时，等权重账号中 uid 靠后的永远进不了短名单 → **饿死**。
2. 快速连续选号时 `time.Now()` 精度不足（Windows ~0.5ms），所有 `lastUsed` 相等，`Before` 全 false → 恒选 `candsAll[0]`。

**现行防护**：存在等权重时对 top5 前洗牌（独立 time-seeded 源，不动注入源）；LRU 兜底改用单调 `usedSeq` 而非墙钟。

**改选号代码时的红线**：不要用墙钟做"最近使用"排序。

## P2 · dirty 被提前清掉导致落盘永久搁置

**现象**（`internal/pool/persist.go:103-105`）：写盘失败后变更永久丢失。

**原因**：旧实现先 `dirty.Swap(false)` 再写盘，写失败时 dirty 已清。

**现行防护**：`Swap` 后写盘失败必须 `Store(true)` 置回，等下一 tick 重试。`Flush` 同款（`persist.go:117-123`）。

## P3 · 损坏的 state.json 被静默丢弃

**现象**（`internal/pool/persist.go:136-145`）：池子以 0 账号启动、credits/冷却/熔断全丢，日志里一个字都没有——运维只看到"账号全没了"。

**现行防护**：`safefile.Read` 先回退 `.bak`；JSON 解析失败必须打日志并**保留原文件**待人工处理。

**改持久化代码时的红线**：任何"读失败就当空"的路径都必须留日志。

## P4 · 网关 401 一次就禁 → 整池打光

**现象**：上游边缘节点抖一下，一堆号被永久禁用。

**原因**：APISIX/nginx 的 401 HTML 页与真实 token 失效**响应体完全一样**，单看 401 分不出来。

**现行防护**（`internal/server/handler.go:1958-1998`）：
- 网关 401 不直接禁，先 `VerifySessionByRefresh` 三分判词：alive（refresh 成功 → 判"降级 token"，清死计数 + 软冷却）、inconclusive（refresh 自身 5xx/429/WAF → 只软冷却）、dead（→ `NoteSessionDead`，**连续 3 次**才禁）。
- 业务码 `12153` 例外：一次即禁（refresh 端点明说 offline session 失效）。

**这条是"踩过一次"的坑，不要回退。**

## P5 · 客户端断连被记成账号的错

**现象**：用户反复刷新/取消，几个账号接连被降权，最后整池"永远解不了封"。

**原因**：传输错误直接喂连败计数，而断连是**结果**不是账号的错。

**现行防护**（`internal/server/handler.go:1174-1178`）：传输错误且 `r.Context().Err() != nil` → 不计罚、outcome 记 `interrupted`。真传输抖动（ctx 未取消）照旧计罚。

## P6 · 模型级限流被记成账号级冷却

**现象**：一个模型抖动 → 整池停摆。

**原因**：6004/14003 是**模型**忙/限流，账号本身健康；按账号冷却会放大成全局不可用。

**现行防护**：6004/14003 一律走 `CooldownSoftForModel` / `CooldownModelBusy`（模型级），切模型豁免；只有其他 429 文案才走账号级 `CooldownSoftRate`（`handler.go:1899-1938`）。

**降级路由的连带陷阱**：换等价模型时冷却必须记在**原模型**名下，记成等价模型会把好的也冷却掉，降级白做（`handler.go:1200-1216`）。

## P7 · soft_rate_max 截断了 6004 的重置墙钟

**现象**：上游明说"8 小时后重置"，网关 2 小时就放号回去再撞。

**现行防护**（`cooldown.go:223-241`）：带解析时间的 6004 直接 `Until = resetAt`，**不受 `soft_rate_max` 截断**；只有无墙钟的有界退避才封顶。

已修提交：`85e44b2` / `67b2a69`（"模型级冷却完整对齐上游重置墙钟，不再被 soft_rate_max 截断"）。

## P8 · 计费/限流措辞互相污染

**现象**：
- 429 body 带"quota exceeded"→ 被误判 `ErrHardCredit` → 硬冷却到次日 04:00，白扔号约 12h。
- `6021 queue.full`→ 被误判软限流 → 与全冷却兜底互相喂成整池停摆（2026-10-15 实案：18 次全落 soft_rate）。
- `14018`（积分耗尽）不先判 → 被归可自愈的软限流，全池冷却时反复兜底选中（issue #175）。

**现行防护**：`Classify` 的判定顺序是精心设计的——状态码优先于关键词、结构化 code 优先于宽泛子串（`internal/upstream/client.go:611-700`）。**改 Classify 顺序前先读完那段注释。**

## P9 · 思考预算吃光 → 空回复

**现象**：`finish_reason=length` 但正文 0 字节，客户端拿到空消息。

**原因**：思考型模型在小 `max_tokens` 下把预算全用在 reasoning 上。

**现行防护**（`internal/server/starved.go:37-87`）：同预算关 `thinking` 重发一次，**每请求只救一次**；限额 <16 不救（救不活）。

已修提交：`b0320cf`。

## P10 · 工具配对断裂被当成账号问题

**现象**：Codex 坏会话反复请求 → 整池健康号逐个被白打、逐个降权，客户端等完全池还是 503。

**原因**：11148「tool calls and tool results do not match」是**请求内容**级问题，上游明示"直接重试无效，请新建任务"。

**现行防护**：`ErrToolMismatch` 400 透传原文 + hint 指向开新会话，不罚号不轮转（`handler.go:1310-1326`）；`tool_pairing.go` 在出站前做双侧对称裁剪防患。

## P11 · costTier 硬过滤导致的"学费"两难

**现象**：已知收费号恒压过未知号 → 免费号永远轮不到 → 永远学不到。

**现行防护**：tier 1（无观测）排在 tier 2（已收费）之前；再用搭车改道（条件探索）让无观测号每 30min 吃到一次真实请求（`pick.go:98-139`）。

**代价**：被改道的那一个真实请求可能落到收费号上。别为了"省这一笔"关掉探索——关掉就等于永远不学。

## P12 · 高价新模型打穿触底号

**现象**（kimi-k3-1 实案）：x1.62 倍率、223 分/百万 token，两笔打穿 100 分的号并触发硬冷却到次日 04:00（最坏 11.5 小时不可用）。

**原因**：保底只查本地实测台账，新模型全池无观测 → "未知"恒等于"放行"。

**现行防护**：`credit_floor` + `modelRateOf` 目录倍率兜底 + `credit_floor_max_rate` 分档（`pick.go:275-307`、`cmd/server/main.go:158-159`）。

**连带**：启动时必须 `warmModelRates` 异步预热倍率表——否则重启后到首次触发之间倍率恒空，兜底形同虚设（`cmd/server/main.go:474-476`、`:520-560`）。

## P13 · 面板静态资源被中间层回放旧版

**现象**（#33）：账号列表能刷新，但积分构成/用量初始化失败。

**原因**：新 HTML 配旧 `app.js` → DOM 结构漂移 → 中途抛异常 → 后半段 `let/const` 不再执行。

**现行防护**：`no-store` + URL 带 sha256 前 8 字节指纹（`internal/panel/index.go:29-54`）。

## P14 · 前端展开状态被轮询重建收回

**现象**：点「展开其余 N 个账号」后什么都不点就自动收起。

**原因**：tbody 每 5s 重建；状态只放 `aria-expanded`/`hidden` 会被下一轮渲染覆盖。

**现行防护**：展开状态存模块级 `restOpen` 对象，键为 tbody id（`internal/panel/app.js:14-17`）。

## P15 · `livecfg.Store` 整体覆盖丢字段

**事实**（当前存在的隐患）：面板保存路径的 `live.Store(...)`（`cmd/server/main.go:693-700`）未回填 `ModelFallback`；该字段只在启动快照里（`main.go:313`）。

**后果**：面板保存任何配置后，`model_fallback` 降级路由在运行期失效（文件里仍在，重启才恢复）。

**新增热字段时**：必须同时改启动装配（`main.go:305-314`）与保存路径（`:693-700`），否则新字段同样会被清成零值。

## P16 · `schedule.growth_concurrency` 不生效

**事实**：该值只写进 `Panel.growthConc`（`main.go:394`、`:741`），读取函数 `growthQueueConcurrency()` **全仓无调用点**（`internal/panel/taskcenter.go:192-203`）。实际并发：后台作业固定信号量 2（`taskjobs.go:111`），手动队列按入口参数 1-4（`taskcenter.go:429`）。

**影响**：配 1 或 4 都不改变排程行为。改这块时要么接上调用点，要么删掉配置项——不要假定它生效。

## P17 · 面板模型页调用不存在的路由

**事实**：`app.js:913` 调 `api('status')`，但面板 mux 无 `/panel/api/status`（`panel.go:190-245`），失败被 `.catch(() => ({}))` 吞掉。

**影响**：模型页拿不到 `/status` 的模型锁信息。要么补路由，要么删调用。

## P18 · Windows 上 `gofmt -l .` 假阳性

**事实**：`core.autocrlf=true` 且无 `.gitattributes`，检出为 CRLF；`gofmt -l .` 会列出全部 303 个文件，但实际上（转 LF 后）无格式差异。

**红线**：不要在 Windows 检出上跑 `gofmt -w`——会把 CRLF 全改 LF，产生巨量无关 diff。

## P19 · 定时任务与聊天无互斥

**事实**：scheduler 不持 per-account 锁、不取在途租约（`internal/scheduler` 内无 `Acquire`）；同账号的定时任务与聊天可能并发。

**风险**：签到/旅行/成长任务与选号同时打同一账号 → 上游频控更易触发。

**现行缓解**：各任务自身的幂等守卫 + 账号间 800ms/1050ms 间隔 + per-account 锁只在 panel 侧（`panel.go:130-142`）。**不是硬保证。**

## P20 · 无出站代理支持

**事实**：全仓未查出 `Proxy`/`ProxyFromEnvironment`。需要代理时只能靠宿主网络/VPN。

**替代**：`dns_servers` / `WB2A_DNS` 可指定解析器（应对 DNS 污染与 Android 无 `/etc/resolv.conf`）。

## P21 · Docker 挂载权限（部署坑）

**现象**：`写入 auths/*.json.tmp 失败: permission denied`。

**原因**：容器以 uid 10001 运行，宿主挂载目录属主不同。

**解法**（`docker-compose.yml:5-12`）：`PUID=$(id -u) PGID=$(id -g) docker compose up -d` / `chown -R 10001:10001 ./auths ./data ./config.json` / `user: "0:0"`。

**连带**：`./config.json` 必须以**文件**形式存在，否则 Docker 把挂载点建成目录 → 启动失败。先 `cp config.example.json config.json`。

## P22 · 本机无 tzdata 时 `TZ=Asia/Shanghai date` 静默回落 UTC

**后果**：发版标签早 8 小时（`AGENTS.md:12-22`）。

**解法**：用 `AGENTS.md` 里带显式 +8h 兜底的脚本。
