# 定时任务与保号

`scheduler` 只负责"到点触发"，动作链路在 `upstream`（协议）与 `panel`（成长队列执行体）。六个小时制任务族 + 两个分钟制循环。

## 触发点

- 小时制：`schedule.checkin_hours`（9,21）/ `travel_hours`（9,21）/ `activity_hours`（10）/ `keepalive_hours`（22）/ `blackcat_hours`（23）/ `growth_hours`（11）。全部按 **CST** 解释，取当天/次日最近一个未过时点（`internal/scheduler/scheduler.go:333-352`）。
- 分钟制：余额刷新每 `balance_refresh_minutes`（默认 5，启动立即一轮）；补领清扫每 `task_sweep_minutes`（默认 15）。
- 启动补跑：`missedToday` 比对 `task-runs.json`，当天漏掉的时点补一轮（等 5s 让网络就绪）（`scheduler.go:529-546`、`internal/scheduler/runstamps.go:34-67`）。
- 手动入口：面板「一键签到/全部旅行/全部活跃/全部保活/全部余额/全部补偿」（`internal/panel/panel.go:229-237`）、`POST /admin/tasks/{name}/run`（需 `admin.enabled`）。
- 前置条件：任务族对应 `*_enabled` 为 true（默认全 true）；空 hours 数组视为未配置、回落默认（**不是禁用**）。

## 数据流路径

`go sch.Run(ctx)`（`cmd/server/main.go:448`）→ 启动补跑 → `nextWake` 求最近槽位 → `waitSlot` 分段等待（段长 1min，每段用**墙钟**重判，对抗 Modern Standby 冻结单调时钟，`scheduler.go:479`、`:502-526`）→ `runBatch`：按任务族启 goroutine（`spreadRunning[kind]` CAS 防同类重叠）→ 账号遍历（可选摊开：FNV 偏移 + 最小间隔钳制，`internal/scheduler/spread.go:33-68`）→ 逐账号调 upstream 端点 → 结果写 pool 状态（仅签到/余额/保活三族）→ 打日志/计数 → `markRan` 落 `task-runs.json`。

## 任务规格表

| 任务 | 触发 | 上游调用 | 状态变更 | 失败处理 |
|---|---|---|---|---|
| 签到 checkin | `checkin_hours`（9,21） | 签到活动状态（只读、fail-open）→ `DailyCheckin` → 余额查询 | `NoteCheckinDone`、`ReenableIfCredits`、`SetCreditsSnapshot`；末尾跑连登/礼包/补偿 | `IsAlreadyCheckin` 视为幂等成功；其余 WARN 后继续查余额 |
| 猫猫旅行 travel | `travel_hours`（9,21） | 猫档案 → 旅行状态 → 领养（协议 + 首次）或派出/领奖 | 无池状态；当日领养失败只本地标记 | 各步 WARN 即 return，不重试；"任务未完成"次日再试 |
| 活跃上报 activity | `activity_hours`（10） | `ReportChatActivity`（v4 UUID conversationId），成功后回读 streak 自检 | 无池状态 | 失败 continue，无重试；账号间 800ms 间隔 |
| token 保活 keepalive | `keepalive_hours`（22），排程路径**只刷临期**（`keepalive_refresh_window` 默认 168h） | `RefreshToken` | 成功：`ClearSessionDead` + 原子写回 auth 文件；`ErrSessionDead`：`NoteSessionDead`（3 次才禁） | 失败 WARN continue，下轮再试；单飞 + 60s 宽限避免双花 refresh token |
| 夜猫子 blackcat | `blackcat_hours`（23）+ 二次校验 23:00–08:00 窗口 | 查 `black_cat` 任务差额 → 跑真实 glm-5.2 对话 + 事件链 | 无池状态 | 查询/执行失败 WARN continue；成功后 800ms 间隔 |
| 成长任务 growth | `growth_hours`（11） | **不打上游**：只调 `GrowthRunner`（面板 `RunGrowthQueueNow`） | 委托面板持久化后台作业 | `GrowthRunner==nil` 静默返回；执行体只对非 disabled 非 global 号启动作业 |
| 余额刷新 | 独立 ticker（5m，启动立即一轮） | 并发 `UserResourceSnapshot`（每号一 goroutine） | `ReenableIfCredits` + `SetCreditsSnapshot`；`Balance.Add` 采样 | 失败 WARN + 401 求证流程（见下） |
| 补领清扫 sweep | 独立 ticker（15m） | 只 accept 待接受的、只 claim 已达标未领的 | 无池状态 | 共用 per-account 锁，占锁即整轮让位 |
| 会话 GC | `gc_interval`（5m，非 scheduler，`cmd/server/main.go:128-140`） | 无上游调用 | 删过期绑定 + 删 Redis 镜像 | 无重试；`StopGC` 幂等 |

## 关键节点详解

| 节点 | 文件位置 | 核心逻辑 | 异常处理 |
|---|---|---|---|
| 槽位计算 | `scheduler.go:376-405` | `enabledSlots` 把 `*Disabled + *Hours + JitterMinutes` 映射成下一触发点；排程与启动补跑共用同一口径 | 全部禁用时空等 rearm/ctx |
| 抖动 | `scheduler.go:323-331` | `FNV32a(kind\|YYYY-MM-DDTHH) % jitterMinutes*60` 秒，**确定性**偏移（重算不会重触发） | `jitter_minutes=0` 仍是整点 |
| 账号摊开 | `internal/scheduler/spread.go:33-68` | 偏移 = FNV(kind\|uid\|日) % 窗口；冲突按 `minGap` 向后推并钳到窗口末尾；遍历按计划时刻排序（否则 uid 序会让 wait 互相堵死） | 手动入口 `on=false` 恒不摊开 |
| 同类防重叠 | `scheduler.go:578`、`:589-592` | `spreadRunning[6]atomic.Bool` CAS，上一批未收尾则跳过本时点 | 跳过不报错 |
| 热重配置 | `scheduler.go:235-258` | `Reconfigure` 写 hours/开关/jitter/spread 后 rearm；空 hours 保留原值 | 面板保存后即生效 |
| 401 求证 | `internal/scheduler/balance_401.go:26-90` | 仅 401 参与；无 refresh token（静态 key/企业号）保持只记日志；refresh 成功 → 判"降级 token"（billing 401 / chat 可用）→ 清死计数；refresh 失败且 session dead → `NoteSessionDead`（3 次才禁）；其他失败不计罚 | `authHealBackoff=30m` 节流，只记 refresh 成功时刻（真死号每轮都试才能累计到阈值） |

## 异常处理

- 调度器与聊天**无互斥**：scheduler 不持 per-account 锁、不取在途租约，同账号的定时任务与聊天可能并发。风险由各任务自身的窗口/幂等守卫承担（签到幂等、保活单飞、旅行状态机）。per-account 锁只在 panel 侧（`internal/panel/panel.go:130-142`），被单任务/一键完成/成长队列/补领清扫/后台作业共用。
- 已禁用账号：默认跳过；`schedule.include_disabled_in_tasks=true` 时**保号四类**（签到/活跃/保活/余额刷新）仍执行——"禁用只关选号，不停保号"。
- 暂停账号（paused）：与 disabled 语义分流，`CountsDetailedWithPaused` 分开统计（`internal/pool/state.go:568-577`）。
- 全局域账号：成长队列与补领清扫明确跳过 global（无个人成长体系）。
- 签到失败：WARN 后仍查余额（余额是解冻判据，不能因签到失败丢掉）。
- 保活失败：不重试，等下轮；`ErrSessionDead` 才计死，连续 3 次禁用。
- 任务落盘失败：只记日志，按空表处理 → 宁可多补一轮。
- 补偿/礼包：只认回执 credit，`credit<=0` 不记"+Nc 到账"；领取失败不重试（交下一期或手动按钮）。
- 余额刷新并发无上限：每号一 goroutine，批结束 `wg.Wait()` 后才写时间戳（避免部分完成就报"已刷新"）。
