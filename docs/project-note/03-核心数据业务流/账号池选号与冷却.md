# 账号池选号与冷却

账号池是全局唯一状态机：所有"这个号现在能不能接单"的判断都收口在这里。聊天、图像、检索、会话粘性四条调用路径共用同一套选号与冷却。

## 触发点

- 每来一个需要上游账号的请求：`Pool.PickExcludingForRealm(tried, reqModel, realm)`（`internal/pool/pick.go:39-41`），或粘性路径 `Pool.PickByUIDForModel(uid, model)`（`internal/pool/state.go:503-530`）。
- 请求失败回流：`internal/server/handler.go:1892-2075` 的 `applyErrorPolicy` 按 `ErrKind` 调对应冷却方法。
- 定时观测回流：签到/余额刷新成功 → `ReenableIfCredits` + `SetCreditsSnapshot`；余额 401 → `NoteSessionDead`。
- 面板手动：pause/resume/disable/revive/model_toggle（`internal/panel/panel.go:748-805`）。
- 前置条件：无。池为空时选号返回 nil，上层回 503。

## 数据流路径

`Pick*()` → 取写锁（`p.mu`）→ 遍历 `byUID` 建候选：跳过 `tried` → 惰性清理过期模型冷却/成本台账 → `selectable()`（在途未满 + 保留积分未触底 + `healthy`/`healthyForModel`）→ `floorBlocked`（触底 + 收费拦截）→ 候选为空则走**全冷却兜底** `pickEarliestExpiryLocked`（取最早到期者）→ `prioritizeLocked` 收窄到"先烧层" → `secondCredits` 求分母 → 成本分层硬过滤（tier 0/1/2）→ 条件探索（tier0 垄断且存在 tier1 且过窗口 → 本轮切 tier1-only）→ 权重预计算 `routingWeightOf` → 等权重洗牌 → 按 (cost1k, weight, uid) 排序 → 截断 top5 → `account_share` 独占抽签（不走截断与 minPickGap）→ 过滤 `now-lastUsed >= 100ms` → 全被刚用过则在**全候选**里按 `usedSeq` 取最旧 → 否则 `pickWeighted` 加权抽签 → 写回 `lastUsed`/`usedSeq` → 返回 `*auth.Auth`。

失败回流：`Classify(status, body)` → `applyErrorPolicy(uid, kind, ...)` → 写对应冷却字段 → 置 dirty → 5s flusher 或 `Flush` 落盘 `state.json`（+ Redis 镜像）。

## 关键节点详解

| 节点 | 文件位置 | 核心逻辑 | 异常处理 |
|---|---|---|---|
| 候选谓词 | `internal/pool/state.go:742-749`、`internal/pool/entry.go:384-398` | 三个截止（`until`/`breakerUntil`/`degradeUntil`）与其他禁用态是或门，任一未到期即不可选——天然"并存取更远者" | 无 |
| 积分保底 | `internal/pool/pick.go:275-307` | 触底（`credits < credit_floor`）+ 收费（本地台账 tier2，或目录倍率兜底）→ 拦截；免费/未知倍率放行 | 全池都拦 → 选号 nil → 503（宁 503 不打穿） |
| 成本分层 | `pick.go:98-156` | tier 0 实测免费 / tier 1 无观测 / tier 2 实测收费；取 `bestTier` 只留同层。用硬过滤而非排序，因为加权抽签会让收费号仍被抽中 | 无观测排在被收费之前，否则免费新号永远轮不到 |
| 条件探索 | `pick.go:110-139` | 每 `cost_explore_interval`（默认 30m）把一个既有真实请求搭车改道给 tier1 号；key = `realm\x1fmodel`，锁内写 timer 天然防重复 | 探索失败走既有错误策略，不产生探测风暴 |
| top5 + LRU | `pick.go:176-228` | 按权重截断 top5 后抽签；top5 全部刚用过时在**全候选**按 `usedSeq` 取最旧（用单调序号而非墙钟，规避 Windows ~0.5ms 精度导致恒选第一个） | 无 |
| 加权公式 | `pick.go:448-476` | `1.0 + (credits/maxCredits)*10*scale + idle`；idle = `min(小时数*0.5, 5.0)`，从未使用给满分；时钟回拨钳 0 | 快过期窗口生效时 credits 项系数降为 0.2（紧迫度为主轴） |
| 快过期紧迫度 | `pick.go:502-533`、`internal/pool/realm.go:27-28` | 窗口外/无批次 = 1；`remain>=window` → 1.5；否则 `sqrt(remain/window)` 插值到 20 | 窗口未注入回退固定倍率 3 |
| 租约 | `internal/pool/pool.go:367-409` | `Acquire` CAS 抢名额，`limit<=0` 永不拒绝；`Release` CAS 递减，≤0 直接返回（幂等） | 抢不到 → 换号 |
| 冷却写入 | `internal/pool/cooldown.go:194-205` 等 | 见"异常处理"逐项 | 每次写后置 dirty |

## 异常处理

- 余额耗尽（402 / 429+14018）：`CooldownUntilTomorrow4AM` 硬冷却到 CST 次日 04:00（04:00 前触发则当天）（`internal/pool/cooldown.go:592-609`）。
- 账号级 429 有重置墙钟：`CooldownSoftRate` 精确冷却到该墙钟，并截断到 `now+soft_rate_max`（`cooldown.go:502-534`）。
- 账号级 429 无墙钟：`d << (streak-1)`，移位上限 16，封顶 `soft_rate_max`；已在软冷却中不推进不延长（`cooldown.go:509-514`、`:549-565`）。
- 6004 模型级限流有墙钟：`CooldownSoftForModel` 写 `modelCooldowns[model].Until = resetAt`，**不受 soft_rate_max 截断**（重置墙钟优先）；切模型豁免（`cooldown.go:223-241`）。
- 6004 无墙钟：只停 (号,模型)，`Hits+1` 驱动有界退避（`cooldown.go:253-272`）。
- 14003 模型繁忙：10s 起翻倍、封顶 1min，已有更晚截止不缩短（`cooldown.go:286-326`）。
- 11102/11158 模型不可用：`BlockModelBackoff` 6h × 2^min(hits-1,4)，封顶 24h；`BlockModelClear` 只清 11102/11158 前缀，不碰 6004（`cooldown.go:345-414`）。
- 熔断：连续失败达 `breaker_threshold`（默认 3）→ `breakerUntil = now + cooldown*2^retryCount`，封顶 `breaker_cooldown_max`（默认 6h）（`cooldown.go:571-588`）。
- 连败降权：未知错误达 `degrade_threshold`（默认 5）→ `degradeUntil = now + degradeDuration`（10m–2h），降权期内再达阈不延长（`internal/pool/degrade.go:20-59`）。
- session dead：`NoteSessionDead` 连续 3 次才 `disableLocked`，阈值内仍可被选中重试（`internal/pool/state.go:35-62`、`internal/pool/entry.go:661`）。
- 全冷却：所有号都不可选时，兜底从冷却号里取 `expiry` 最早者并打 WARN；**disabled/paused 永不参与兜底**（`pick.go:311-360`）。
- 在途占满：`Acquire` 失败 → 解绑粘性 + 换号；整池占满则兜底也跳过 → nil → 503（`pick.go:339-342`、`handler.go:1112-1123`）。
- 手动关模型优先于一切自动恢复：`modelOffed` 判在 `modelCooled` 与账号级冷却之前（`internal/pool/entry.go:439-452`）。
- 状态落盘失败：置回 dirty 等下轮重试；日志首败 / 每 12 次 / 恢复各一条（`internal/pool/persist.go:23`、`:100-123`）。
