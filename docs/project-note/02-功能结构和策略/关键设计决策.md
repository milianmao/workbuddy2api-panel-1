# 关键设计决策

每条按「决策 → 背景 → 考虑过的替代 → trade-off」记录。所有背景均来自代码注释或 README 里的实测记录，不臆测。

## D1 · 不跟上游 1.x，用上海时间戳版本号

**决策**：标签形如 `v2026.9.26.711`，日期 + 时不补零 + 分两位（`AGENTS.md:3-10`）。

**背景**：本仓是下游 fork，与上游 `1.x` 语义不对应；时间戳天然单调、无冲突、不需要维护 changelog 里的映射表。

**代价**：不是 semver，无法表达"破坏性变更"；GHCR 也不会因此产生 `1.2.3` 类镜像 tag（`docker-ghcr.yml:4-10`）。

**踩过的坑**：本机（Windows/git-bash）无 tzdata 时 `TZ=Asia/Shanghai date` 会静默回落 UTC，标签整整早 8 小时。修复是显式 +8h 兜底（`AGENTS.md:12-22`）。

## D2 · 不做静态模型兜底目录

**决策**：`/v1/models` 纯动态拉取，失败返回空列表 + 5min 负缓存。

**背景**：静态表会随上游变动腐化，且列出不可用模型比不列更糟——客户端会选到必然失败的模型。

**代价**：上游目录接口挂掉时客户端拿不到任何模型。

## D3 · global 目录只认桌面端 UA 族

**决策**：国际版目录只收官方**桌面端** UA 族下发的模型；IDE/CLI 族与企业端点只用来补全同 id 的 context/efforts/倍率。

**背景**（issue #216）：另两族的独有模型实测在 chat 端点回 `11102`（该后端无此模型）。列出来只会让客户端选到死模型。

**代价**：桌面端族未下发的模型即使可用也不列。

## D4 · 不给请求体加 `conversation_id`

**决策**：仓库不提供该开关，`internal/probe/probe169.go` 保留测量工具但 `//go:build ignore`。

**背景**（issue #169，2026-10-21 真机 A/B）：上游前缀缓存按**内容**共享，加不加、填什么值命中率完全一致（`deepseek-v4.1-flash` 90.9/90.9、`glm-5.2` 99.9/99.9、`deepseek-v4-pro` 98.6/98.6）。字段本身不会被拒（三发 200），但加了没有任何收益。

**替代方案（已否定）**：加字段试图提高缓存命中——实测无效。

## D5 · 成本分层用硬过滤 + 条件探索，不用"学费探测"

**决策**：按该 (账号, 模型) 的**实测**扣费分三层（0 免费 / 1 无观测 / 2 收费），只保留最优层；当免费层垄断且存在无观测号时，每 30min 把一个既有真实请求**搭车改道**给无观测号（`internal/pool/pick.go:110-139`）。

**背景**：新号的限免状态只能靠实测发现。若已知收费号恒压过未知号，那台免费的号永远轮不到，也就永远学不到。

**替代方案（已否定）**：主动发探测请求——会新增上游流量、放大 WAF 暴露面。改道是零新增请求。

**代价**：免费层垄断期间，被改道的那一个真实用户请求可能落到收费号上（单次成本）。

## D6 · 积分保底 + 目录倍率兜底

**决策**：`credit_floor`（默认 100）以下的号不接实测收费模型；无实测观测时用上游目录倍率兜底，`credit_floor_max_rate` 控制"便宜的新模型可放行"。

**背景**：kimi-k3-1 实案——全池无观测 → 保底全放行 → 两笔打穿 100 分的号并硬冷却到次日 04:00（最坏约 11.5 小时不可用）。

**代价**：全池触底且全 tier 2 时选号返回 nil，网关回 503——**宁 503 不打穿**（硬语义，`pick.go:275-307`）。

## D7 · 6004 模型级限流 → 同账号换等价模型

**决策**：`pool.model_fallback` 表，仅 `6004`（`ErrSoftRate` + `IsModelRateLimit`）触发；**冷却仍记在原模型名下**；不写持久状态。

**背景**：6004 是模型级限流（实测见过 8 小时窗口），此时账号本身健康、等价模型完全可用。让客户端等 8 小时不合理。

**关键陷阱**：若把冷却误记成等价模型，会把本来好好的等价模型也冷却掉，降级白做（`internal/server/handler.go:1200-1220` 注释）。

**不适用**：`11102`/`11101`/普通 429/5xx——换模型救不了或不该救。

## D8 · 14003「模型繁忙」独立短窗口

**决策**：10s 起、翻倍、封顶 1min；不走 `soft_rate` 的 600s→2h 阶梯。

**背景**：14003 是"模型繁忙"，没有恢复时刻，上游文案就是让客户端换模型/稍后重试——**不是这个号被限流**。套 600s 阶梯会让一次抖动变成十分钟不可用（`internal/pool/cooldown.go:286-289`）。

## D9 · 网关 401 先 refresh 求证再计死

**决策**：网关 401（APISIX HTML 页，无业务信封）不直接禁用，先 `VerifySessionByRefresh` 三分判词 alive/dead/inconclusive；dead 才计死，连续 3 次才禁用。

**背景**：边缘节点抖动也会回 401 HTML，一次就禁会在上游抖一下时把整池打光（**这个坑本项目踩过一次**，`internal/server/handler.go:1955-1975` 注释）。

**对比**：业务码 `12153`（refresh 端点明说 offline session 失效）→ 一次即禁。

## D10 · 提示词三模式，默认 passthrough

**决策**：`passthrough`（默认）/ `custom`（替换 system）/ `append`（开头连续 system 块后插入）。

**背景**：客户端（Claude Code/Codex 等）在 system 注入固定模板句，上游按逐字匹配误杀（issue #36/PR39 的 `11-128`）。`custom` 从源头消灭 system 来源的指纹误报，但会改变客户端行为。

**代价**：`passthrough` 下仍可能撞误报，兜底是首次拦截时切 `prompt.Degraded` 中性提示词到次日 00:00 CST（`internal/server/degrade.go:22-52`）。

**注意**：README 的"字段速查"表写 `prompt.mode` 默认 `custom`、以及"关键断言 ↔ 代码出处"表引 `cmd/server/config.go:148`——与代码不符。代码事实是 `c.Prompt.Mode = "passthrough"`（`cmd/server/config.go:413`），注释写"缺省 passthrough：透传客户端原始 system（对齐上游；custom 由用户显式选择）"，自 2026-09-15 的 `8f812d3` 起如此。**以代码为准**。

## D11 · 会话粘性失败即解绑

**决策**：粘性号不可用/被抢/失败 → `Unbind` 并回落普通轮换；成功后重新 `Bind` 覆盖旧绑定。

**背景**："限额后换不动号"的正解——按模型解析：绑定号在**当前模型**被 6004 限额时视为不可用，重新分配，而不是钉在限额号上反复失败（`internal/server/handler.go:862-875`）。

**代价**：绑定会漂移，前缀缓存可能失效一次。

## D12 · 会话键可内容派生

**决策**：`conversation_id` → `conversationId` → `prompt_cache_key` → 派生键（`SHA-256(system + "\x00" + 首条 user 签名)` 前 16 字节，前缀 `d-`）；带 `user_id` 时不派生。

**背景**：客户端不发 `conversation_id` 时，通用 OpenAI 客户端也能享受粘性。但只发 `user_id` 的客户端若走 user 维度派生，多段对话会互相覆盖前缀缓存（issue #5：`glm-5.3` 大上下文周期性命中率掉到 0.2%）。

**关键**：派生键只供**缓存槽**使用，账号绑定仍只认 `sessKey`，不复活 user 维度粘性（`handler.go:856-866`）。

## D13 · 强制出站 `stream:true`

**决策**：无论客户端 `stream` 是什么，出站一律 `stream:true`；非流式由本地聚合。

**背景**：上游只可靠地支持 SSE；非流式路径在长生成上易断。

**代价**：非流式请求要等完整生成完成（内存里聚合整条流）。

## D14 · 首帧否决

**决策**：首字节写出前遇 error 帧/零有效帧 → 不写字节直接换号。

**背景**：一旦写出头就无法改状态码；空流必须先写 error 帧再补 `[DONE]`，客户端才能正确报错而不是拿到"成功但空"。

## D15 · 工具配对修复独立于脱敏

**决策**：`tool_pairing.go` 对所有模型生效、与 `sanitize.go` 完全独立：`repackToolResultBlocks` 把插在 `assistant.tool_calls` 与结果之间的非 tool 消息挪到组后；`cleanupOrphanToolCalls` 按同一份 `keepCalls` 双侧对称裁剪。

**背景**：请求内容级配对断裂（11148）会让上游回"直接重试无效，请新建任务"。修复是**请求整形**而非内容审核，所以不能混进 sanitize。

## D16 · 空输出补救一次

**决策**：`finish_reason=length` + 正文 0 字节 + 无 tool_calls + 有显式限额 → 同预算关 `thinking` 重发一次；限额 <16 不救。

**背景**：思考型模型在小 `max_tokens` 下会把预算全用在 reasoning 上，正文空。每请求只救一次，避免放大。

## D17 · 日/突发预算只统计"已观测"扣费

**决策**：`budget.add` 只加**已观测** credit，不估算；日切按 CST 惰性归零。

**背景**：估算会漂移；宁可少拦也不误拦。

## D18 · 日志归档只写元数据

**决策**：`reqlog` JSONL 只写请求元数据（模型、耗时、状态、来源），**不写**提示词、响应正文、Authorization。来源（IP/UA）可按开关关闭。

**背景**：IP 属个人信息，共享部署可关（`logging.request_client_info`，热生效）；归档队列满时丢弃并计数，绝不让日志写盘阻塞模型请求。

## D19 · 面板鉴权无 cookie / 无服务端会话

**决策**：浏览器把 api_key 存 `localStorage`，每请求带 `Authorization: Bearer`。

**背景**：面板是单用户运维界面，引入会话/CSRF 体系收益低；`frame-ancestors 'none'` + `form-action 'none'` + 严格 CSP 已挡住点击劫持与表单外发（`internal/panel/index.go:67-79`）。

**代价**：XSS 可直接读走 key——因此 `esc()` 5 字符转义是硬要求（`app.js:88-95`）。

## D20 · 新号落池默认暂停选号

**决策**：导入与 OAuth 登录进来的号一律 `Add → Revive → Hold`，即落池后处于"暂停选号"（`internal/panel/import.go:418-424`、`login.go:218-225`）。

**背景**：刚登录的号还没观察过，直接接单可能立刻撞限流/风控。暂停状态让人先看状态再决定（最近提交 `66908b3`/`320bedd` 端到端钉死此语义，并确认"解冻"清不掉）。

**代价**：批量导入后需显式恢复选号。
