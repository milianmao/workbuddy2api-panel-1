# 核心功能模块

项目按"对外协议"和"运维动作"两条轴切模块。下表是全部功能域，每域标注入口、职责边界与交互面。

## 功能域总表

| # | 功能域 | 入口 | 职责 | 不负责 |
|---|---|---|---|---|
| 1 | 聊天补全 | `POST /v1/chat/completions`（`internal/server/handler.go:192`） | 协议校验、模型解析、选号、轮转、SSE 中继、用量记账 | 上游协议细节（upstream）、账号状态（pool） |
| 2 | Responses（Codex） | `POST /v1/responses`（`handler.go:193`） | Responses 入站 → 内部 chat 方言 → 回写 `response.*` 事件族 | 保存 `previous_response_id`（不支持） |
| 3 | Anthropic Messages | `POST /v1/messages`、`/messages`（`handler.go:199-200`） | Messages 入站 → chat → 回写 Messages JSON/SSE | 回传 thinking（上游无 signature） |
| 4 | 图像 | `POST /v1/images/generations`、`/edits`（`handler.go:197-198`） | 文生图/图生图，仅 cn 域 | 非图像模型 |
| 5 | 检索/抓页 | `POST /v1/search`、`/v1/fetch`（`handler.go:202-204`） | 透传上游 agenttool；`deep:true` 走综述式 | 对话语义 |
| 6 | 模型目录 | `GET /v1/models`（`handler.go:208`） | 动态拉取 + 缓存 + hidden/alias/前缀处理 | 静态兜底（纯动态） |
| 7 | 账号池 | `internal/pool` | 选号、租约、冷却、熔断、降权、保底、持久化 | 上游协议、HTTP |
| 8 | 会话粘性 | `internal/session` | 会话键 → 账号绑定，TTL 滚动，Redis 镜像 | 选号权重 |
| 9 | 定时任务 | `internal/scheduler` | 签到/旅行/活跃/保活/夜猫子/余额刷新/补领清扫 | 任务队列执行体（在 panel） |
| 10 | 成长任务 | `internal/panel/autotask.go` + `taskcenter.go` + `taskjobs.go` | 任务扫描、accept、动作执行、领奖、作业持久化 | 排程时点（scheduler 注入回调） |
| 11 | 账号接入 | `internal/panel/login.go` / `import.go` / `apikey.go` | OAuth 设备流、JSON 导入、静态 Key | 上游登录协议（loginsite） |
| 12 | 观测 | `overview`/`logs`/`error_summary`/`request_logs`/`usage`/`balance_history`/`credit_history` | 面板只读视图 | 采集（reqlog/usage/balance/credithist） |
| 13 | 护栏 | `budget.go`/`degrade.go`/`wafip.go`/`starved.go`/`capacity` | 日/突发预算、提示词降级、IP 级 WAF、空输出补救 | 账号级冷却（pool） |
| 14 | 配置 | `GET/POST /panel/api/config` | 校验、原子写、热应用、需重启项提示 | 环境变量（启动期） |
| 15 | 告警 | `internal/alert` | 健康数/熔断/WAF 阈值 → webhook | 面板展示 |

## 模块间交互矩阵

行 = 发起方，列 = 被调方；`→` 表示调用，`⇒` 表示回调注入。

| | pool | upstream | session | scheduler | panel | livecfg | redis |
|---|---|---|---|---|---|---|---|
| **server** | → 选号/租约/冷却 | → ChatStream/目录 | → 绑定解析 | — | ⇒ 挂载 `/panel/` | → 读热配置 | → 经 session |
| **panel** | → 状态/操作 | → 账户动作/目录 | → 计数 | ⇒ 触发作业 | — | → 读/写热配置 | → 读模式名 |
| **scheduler** | → 状态/余额 | → 签到/旅行/保活 | → 会话 GC 解绑 | — | ⇒ `RunGrowthQueueNow` | — | — |
| **pool** | — | ⇒ `SetModelRateOf` 回调 | — | — | — | — | → 快照 |
| **upstream** | — | — | → 会话头族 | — | — | — | — |

三条"不许反向"依赖：
- `pool` **不** import `upstream`（倍率经 `SetModelRateOf` 注入，`internal/pool/pool.go:78-85`）。
- `scheduler` **不** import `panel`（队列执行体回注，`cmd/server/main.go:392-393`）。
- `upstream` **不** import `pool`（无状态，`internal/upstream/client.go` 无 pool import）。

## 各域的关键边界

**1 聊天补全**：网关是**协议翻译 + 路由 + 改写**，不是业务逻辑层。它不做内容审核、不改用户语义、不缓存响应。请求体无大小上限（`max_body_mb` 已移除，`handler.go:721-728`）。

**6 模型目录**：纯动态、无静态回落。CN 10min 缓存 + 失败 5min 负缓存（`handler.go:386-400`）；global 1h/5min（`internal/upstream/global_models.go:240-243`）。global 目录**只认官方桌面端 UA 族**下发的模型——另两族独有模型实测在 chat 端点回 11102，列出来只会让客户端选到死模型（README「API 端点」节）。

**7 账号池**：唯一的状态机。所有"这个号现在能不能接单"的判断收口在 `entry.healthy` / `healthyForModel`（`internal/pool/entry.go:384-398`、`:439-458`），选号侧只读这些谓词。

**9 定时任务 vs 10 成长任务**：scheduler 只负责"到点触发"，具体动作链路（扫描→accept→执行→领奖）唯一实现在 panel；`sch.SetGrowthRunner(pn.RunGrowthQueueNow)` 注入（`cmd/server/main.go:392`）。这样避免 scheduler → panel 循环依赖。

**13 护栏**的措辞边界：护栏**只影响路由与提示**，不改变透传字节。唯一例外是提示词降级（`internal/server/degrade.go`），它按设计改写 system 消息。

## 功能开关总览

| 开关 | 默认 | 关掉后 |
|---|---|---|
| `api_key` 空 | 空值 | 全部端点不鉴权（公网必须设） |
| `global.enabled` | true | 不路由 global 域、不列 `global:` 模型 |
| `session_sticky.enabled` | true | 纯轮换，无绑定 |
| `pool.prefer_expiring` | true | 只按常规加权路由 |
| `pool.credit_floor` | 100 | 不拦触底号 |
| `pool.cost_explore_interval` | 30m | 不做成本探索 |
| `prompt.mode` | passthrough | custom/append 见 [设计模式与策略](../02-功能结构和策略/设计模式与策略.md) |
| `schedule.*_enabled` | true | 对应定时任务停跑（面板手动入口仍在） |
| `admin.enabled` | false | `/admin/tasks/*` 不注册（404） |
| `metrics.enabled` | false | `/metrics` 不注册（404） |
| `alerting.enabled` | false | 不推 webhook |
| `budget.*` | 0 | 0 = 不拦 |
