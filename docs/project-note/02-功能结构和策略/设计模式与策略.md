# 设计模式与策略

本项目不用框架，模式都是手工实现的。下面每一条都能在代码里指出唯一实现点——这是"信息只存一处"的前提。

## 1. 不可变快照 + 原子指针（热配置）

`livecfg.Holder{p atomic.Pointer[Snapshot]}`：读方 `Load()` 拿一致视图，写方 `Store()` 整体替换，无锁无竞争（`internal/livecfg/livecfg.go:72-95`）。

代价：**整体覆盖语义**——`Store` 不合并旧值。因此新增热字段时必须同时改启动装配与面板保存两处，否则保存后该字段变零值。当前热字段：`api_key`、`cooldown.soft_rate`、`sanitize_blacklist_fingerprints`、`record_client_info`、`models.hidden`、`models.aliases`、`model_fallback`（`cmd/server/main.go:305-314`、`:693-700`）。

## 2. 回调注入破循环依赖

| 场景 | 注入点 | 原因 |
|---|---|---|
| pool 查上游模型倍率 | `p.SetModelRateOf(func(realm,model) string)`（`cmd/server/main.go:158-159`） | pool 不 import upstream |
| scheduler 跑成长队列 | `sch.SetGrowthRunner(pn.RunGrowthQueueNow)`（`main.go:392`） | scheduler 不 import panel |
| scheduler 跑补领清扫 | `sch.SetSweepRunner(pn.RunTaskSweepNow)`（`main.go:393`） | 同上 |
| 余额变动留痕 | `up.SetCreditObserver(creditHist.Observe)`（`main.go:342`） | upstream 不 import credithist |
| 会话粘性可用账号 | `session.Config.AvailableForModel`（`main.go:129-137`） | session 不 import pool |

约定：**回调不得反向调用持有方的方法**（注释明写，`internal/pool/pool.go:78-85`），否则在锁内调用会造成自死锁。

## 3. 硬过滤优先于软排序

选号中"成本分层"是**硬过滤**而非排序，理由写在代码里：`pickWeighted` 会在候选内加权随机，只排序的话收费号仍有机会抽中，达不到"优先免费"的语义（`internal/pool/pick.go:98-107` 上方注释）。

同一哲学的三处：
- `account_priority` 硬收窄到"先烧层"（`pick.go:84`）——排序只改抽签次序，高优先级号仍会被抽到。
- `account_share` 独占抽签且**不走 top5 截断**（`pick.go:204-206`）——低占比号否则永远进不了短名单。
- 积分保底在候选循环里直接 `continue`（`pick.go:69`）。

## 4. 分层冷却（最细粒度的惩罚）

惩罚粒度从粗到细，互不叠加（或门，取更远者）：

| 粒度 | 状态字段 | 触发的错误 |
|---|---|---|
| 账号永久 | `disabled` | session dead 达阈、面板手动 |
| 账号暂停 | `paused` | 面板手动，只关选号不停保号 |
| 账号冷却 | `until` | 硬积分（到次日 04:00）、软限流（指数退避） |
| 账号熔断 | `breakerUntil` | 连续失败达阈 |
| 账号降权 | `degradeUntil` | 未知错误连败达阈 |
| (账号,模型) | `modelCooldowns[model]` | 6004/14003/11102 |
| (账号,模型)手动 | `modelOff` | 面板手动关模型，优先于一切自动恢复 |

判据收口在 `entry.healthy` / `healthyForModel`（`internal/pool/entry.go:384-398`、`:439-458`）。**为什么必须分模型级**：实测同号换模型立刻可用，按账号冷却会把一个模型的抖动放大成整池停摆（`internal/server/handler.go:1900-1908`）。

## 5. 墙钟对齐优于指数堆加

上游 429/6004 若给了重置时间，一律**精确冷却到该墙钟**，绝不指数堆加（`handler.go:1899-1912`）。只有拿不到时间时才走 `base << (streak-1)` 有界退避，封顶 `soft_rate_max`（`internal/pool/cooldown.go:549-565`）。

例外：14003「模型繁忙」没有恢复时刻，给独立短窗口（10s 起、封顶 1min），不套 600s→2h 阶梯（`cooldown.go:286-289`、`handler.go:1918-1926`）。

## 6. fail-fast：与账号无关的错误不轮转

同一 body 换任何账号都会得到同样结果 → 立即终止轮转并透传上游原文。清单（`handler.go:1240-1350`）：

| 错误 | 原因 |
|---|---|
| `ErrContentBlocked` | 内容审核，换号撞同一审核 |
| `ErrPromptTooLong` (11115) | 上下文超限是请求的问题 |
| `ErrImageInvalid` | 图片数据无效 |
| `ErrUpstreamBusy` (6021) | 渠道队列满，换号撞同一堵墙 |
| `ErrToolMismatch` (11148) | 工具配对断裂，上游明示"请新建任务" |
| `ErrBadParams` / `ErrModelParamInvalid` | 参数被供应商拒绝 |
| 传输错误 + ctx 已取消 | 客户端走了，换号是白打 |

WAF IP 级拦截也走 fail-fast：60s 窗内 ≥2 个**不同** UID 命中 WAF 403 → 判 IP 级、激活 60s、当下 `break` 不放大请求量（`internal/server/wafip.go:29-35`、`handler.go:1362-1364`）。

## 7. 首帧否决（无痕换号）

SSE 首字节写出前遇 error 帧或零有效帧 → `HeadVetoError`，**不写任何字节**就返回，上层换号，客户端完全无感（`internal/upstream/sse.go:28-45`）。一旦写出注释行，窗口关闭，后续只能走"已提交头"路径（补 error 帧 + `[DONE]`）。

## 8. 双写 + 择新恢复（持久化）

本地 `state.json` 与 Redis 快照并存，启动时 `RestoreFromSnapshot` 按规则择新：本地不可用 → 用快照；本地存在且 `!ModTime().After(savedAt)` → 用快照；否则本地优先（`internal/pool/persist.go:70-87`）。采用快照时置 dirty，让下次落盘物化回本地（`:270-279`）。

写盘用 `safefile.WriteKeep`：同目录 tmp → `Sync` → `rename` → 旧内容留 `.bak`（`internal/safefile/safefile.go:92-117`）。**为什么 tmp+rename 不够**：rename 只保证读者看到完整文件，不保证内容落盘——掉电可能留下长度正确、内容全 0 的文件（`safefile.go:1-14`）。

## 9. Redis 只做旁路，永不阻塞

`redisstore` 全部写操作 fire-and-forget（后台 goroutine + 失败仅 debug），读只发生在启动（`internal/redisstore/redisstore.go:1-10`）：Upstash 走公网 TLS，单次 RTT 50–300ms，同步写会把面板和请求路径拖死。写槽信号量 8、单写 5s 超时、`Close` 时 10s 排空兜底。

## 10. 惰性清理而非后台 GC

`pick()` 每次遍历候选时顺手 `pruneExpiredModelCooldowns(now)` / `pruneExpiredModelCosts(now)`（`internal/pool/pick.go:64-65`）。理由：两个 map 都不无限膨胀，status 只读遍历天然跳过过期项，但内存条目必须真正删除——选号路径是唯一高频入口，挂在那里零额外成本。

同理：预算日切在 `admit()` 里惰性归零（`internal/server/budget.go:184-196`）。

## 11. 单飞（single-flight）刷新

`RefreshToken` 用 `refreshing` 标记保证同一账号同时只有一个刷新在飞，其余等待；成功后 60s 内复用 `renewed` 结果，强制刷新不吃宽限；网络 30s 超时在锁外执行（`internal/upstream/client.go:1121-1204`）。理由：并发刷新会让上游轮换 refresh token，先到的写盘、后到的把先到的作废。

## 12. 指纹 + no-store 双保险（静态资源）

`Cache-Control: no-store` + URL 带 sha256 前 8 字节指纹（`internal/panel/index.go:29-54`）。理由：反代缓存/浏览器扩展/企业网关只要回放一次旧 `app.js`，新 HTML 配旧 JS 就会因 DOM 漂移中途抛异常，后半段 `let/const` 不再执行（`index.go:31-38` 记录了受控复现）。

## 13. 单一事实来源（同一口径只写一次）

| 口径 | 唯一实现 | 调用方 |
|---|---|---|
| Bearer 鉴权 | `httpauth.VerifyBearer` | server（`handler.go:263`）、messages（`messages.go:28`）、panel（`panel.go:260`） |
| 健康判定 | `entry.healthy` / `healthyForModel` | pick、status、capacity、metrics |
| 积分保底 | `floorBlockedForRealmModel` | pick 普通路径 + 粘性路径 |
| 登录站点表 | `internal/loginsite` | panel/login + cmd/login |
| 日期边界 | `internal/cst` | pool、scheduler、budget、upstream |
| 上游错误分类 | `upstream.Classify` | handler 兜底 + 各端点 |

改口径时只改这一处；复制实现是本项目明令禁止的反模式（`internal/httpauth/httpauth.go:1-8` 记录了"各自复制一份字符串比较"的旧坑）。
