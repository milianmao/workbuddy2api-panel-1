# 编码规范

规范来源只有两处：`AGENTS.md`（发版硬规则）+ 代码里已经稳定下来的事实。没有 linter 配置，所以"规范"= 能被 code review 指出的既有惯例。

## 命名约定

| 对象 | 约定 | 例 |
|---|---|---|
| 包名 | 小写单词，不缩写 | `pool`、`upstream`、`reqlog`、`credithist` |
| 导出类型 | 名词或名词短语 | `Pool`、`Status`、`ErrKind`、`RealmHealth` |
| 未导出结构 | 小写，常带限定词 | `entry`、`stateAccount`、`queueItem`、`degradeGate` |
| 构造函数 | `New` / `NewXxx` | `pool.New(path)`、`server.NewHandler(cfg)`、`usage.New(path)` |
| 注入配置 | `SetXxx(...)`，返回 void | `SetBreaker`、`SetModelRateOf`、`SetCreditFloor` |
| 状态变更 | `NoteXxx`（记一次观测）/ `SetXxx`（整写）/ `CooldownXxx`（写冷却） | `NoteSuccess`、`SetCreditsSnapshot`、`CooldownSoftForModel` |
| 布尔谓词 | `is/has/can/needs` 或直接形容词 | `isChatEntry`、`hiddenModel`、`selectable`、`NeedsRefresh` |
| 单字母/短名 | 仅限极短作用域与惯用法 | `p *Pool`、`e *entry`、`r *http.Request`、`uid`、`rc`（响应流） |
| JSON 字段 | snake_case | `session_dead_fails`、`credits_expires_at`、`cool_remaining_sec` |
| 错误码字符串 | snake_case 全文 | `no_healthy_account`、`model_unavailable`、`content_blocked` |

出处示例：`internal/pool/pool.go:148-355`（Set*）、`internal/pool/state.go:213-268`（Note*/Set*）、`internal/pool/cooldown.go:194-592`（Cooldown*）。

## 注释规范（最鲜明的项目特征）

7763 行注释（`grep -c '^// '`，internal + cmd），比例约 1:11 源代码行。注释不是描述「做了什么」，而是**记录为什么这样、以及踩过什么坑**：

| 类型 | 例 |
|---|---|
| 为什么不用更直观的做法 | "为什么用硬过滤而非仅排序：pickWeighted 会在候选内加权随机，只排序的话收费号仍有机会抽中"（`internal/pool/pick.go:100-104`） |
| 实测证据 | "2026-10-15 实案：18 次全落 soft_rate，上游 PR #180/#185"（`internal/upstream/client.go:644-648`） |
| 历史事故复盘 | "边缘节点抖动也会回 401 HTML，一次就禁会在上游抖一下时把整池打光（这个坑本项目踩过一次）"（`internal/server/handler.go:1955-1960`） |
| issue/PR 关联 | 大量 `issue #N`、`PR #N` 引用 |
| 反模式警告 | "不要为了「统一」把 base 写死成一个域，老账号的 token 只在签发域可用"（`cmd/server/config.go:152-155`） |

注释里保留**具体日期、数字、案发现象**——这是可检索的运维知识，不是冗余。

## 错误处理

| 约定 | 说明 |
|---|---|
| 分类优先 | 所有上游错误先过 `upstream.Classify` 归到 `ErrKind`，再按 Kind 决策（`internal/upstream/client.go:611-757`） |
| 包装用 `%w` | 需要 `errors.Is` 的地方必须 `%w`（`cmd/server/main.go:66-68` 注释："errors.Is 才能看穿 Load 里 fmt.Errorf("%w") 的包装；os.IsNotExist 不行"） |
| 不吞错 | 失败分支必须留日志或状态；面板可关的只有 INFO 噪音（`e2d0ded`/`185ce77` 把"模型未调工具的正常收尾"降为 INFO） |
| 错误透传 | 请求级错误把上游原文放 `message`，不编造替代文案（`handler.go:1240-1350` 多处明确写"禁止固定词覆盖"） |
| fail-fast 判据 | 同一 body 换任何账号都会失败 → 立即终止轮转（见 [设计模式与策略](../02-功能结构和策略/设计模式与策略.md)） |

## 并发约定

| 约定 | 说明 |
|---|---|
| 锁内不做 IO | Redis 写 fire-and-forget；文件写只在 Flush/显式 save（`internal/pool/persist.go`） |
| 声明式注释锁的边界 | 结构体字段注释写清"由哪个锁保护"（`internal/pool/pool.go` 每个字段都有） |
| atomic + 整体替换 | 热配置用 `atomic.Pointer` 快照，避免细粒度锁 |
| 回调不得反向调用 | 注入的回调内禁止调用持有方方法（会自死锁），注释明写（`internal/pool/pool.go:78-85`） |
| 幂等释放 | `Release` CAS 递减 ≤0 直接返回（`internal/pool/pool.go:393-409`） |

## 文件组织

| 约定 | 实例 |
|---|---|
| 一文件一关注点 | `internal/pool/` 拆 12 个源文件：`pick.go` 选号 / `cooldown.go` 冷却 / `degrade.go` 降权 / `persist.go` 落盘 / `realm.go` 分域 / `toggle.go` 手动开关 |
| 大文件靠注释分节 | `handler.go`（2220 行）用 `// ─────` 横线分节（`:2078-2080`）；`app.js`（4669 行）用 `/* ── 标题 ── */` 分节（26 处） |
| 测试与源同目录同名前缀 | `handler.go` ↔ `handler_test.go` + 主题细分测试（`gates_test.go`、`starved_test.go`） |
| 内嵌资源放包内 | `internal/panel/index.html` / `app.js` / `theme.js` |

## 前端规范

| 约定 | 说明 |
|---|---|
| 无框架、无构建 | 纯函数 + 字符串拼接；不许引第三方库 |
| 所有插值过 `esc()` | 5 字符转义（`&<>"'`），防属性注入（`internal/panel/app.js:88-95`） |
| 状态必须在 DOM 之外 | 会被轮询重建的区域（账号表 tbody），展开/筛选状态存模块级对象（`app.js:14-17` 注释：否则下一轮渲染会收回） |
| 模块级 `let/const` 声明放顶部 | 避开 TDZ；首次 `go()` 延后 `setTimeout(0)`（`app.js:449-456`） |
| 不得内联脚本 | CSP 无 `unsafe-inline`，主题脚本必须外链 `theme.js` |
| 中文文案硬编码 | 无 i18n 框架，`<html lang="zh-CN">` |

## Go 版本与依赖

- Go 1.26.10，三处必须一致：`go.mod`、`Dockerfile:2`、CI（用 `go-version-file: go.mod` 自动跟随）。
- 新增直接依赖前先确认标准库做不到：当前只有一个直接依赖 `redis/go-redis/v9`（`go.mod:5`）。
- `CGO_ENABLED=0` 是硬约束（纯静态二进制 + 交叉编译）。
