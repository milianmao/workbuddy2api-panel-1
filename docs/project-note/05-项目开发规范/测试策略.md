## 框架与工具

只用标准库 `testing`：

| 工具 | 用途 |
|---|---|
| `httptest.NewServer` | 假上游（`internal/upstream/sanitize_test.go:445-448`、`internal/scheduler/activity_test.go:56`、`internal/panel/login_paused_test.go:29`） |
| `httptest.NewRecorder` + `httptest.NewRequest` | handler 级请求（`internal/server/handler_test.go:137-138`） |
| `roundTripFunc`（自定义 `http.RoundTripper`） | 注入 Transport，精确控制上游响应（`handler_test.go:45-49`、`:66-68`） |
| `t.TempDir()` | 文件/状态测试（`internal/auth/auth_test.go:41,67`、`internal/balance/balance_test.go:163`） |
| `t.Setenv` | 环境变量覆盖（`internal/panel/config_env_test.go:14`） |

| `t.Run` 表驱动 | 主流组织方式（`pool_test.go:606-607`、`handler_test.go:1761-1762`、`sanitize_test.go:544-550`） |
| `testing.Short()` | 耗时/需要外部输入的用例 |
| `os.CreateTemp(t.TempDir(), …)` + node | 跑 `app.js` 纯函数断言（`internal/panel/frontend_test.go:109`） |

**无** testify/gomock/ginkgo/sqlmock。

## Mock 策略

| 层 | 做法 | 例 |
|---|---|---|
| 上游 HTTP | 两种：`httptest.NewServer` 起真 HTTP 服务（验证头/编码/流），或 `roundTripFunc` 注入（验证请求内容） | `sanitize_test.go:445`；`handler_test.go:48` |
| 上游 Client | 构造 `upstream.Client` 后替换 `HTTP`/`ChatHTTP` 的 Transport 字段 | `handler_test.go:45-56` |
| 存储 | `t.TempDir()` 真文件，不 mock `safefile` | `auth_test.go:41` |
| 时间 | 不用 clock 接口；需要时用短时长 + 轮询断言，或注入 `SetRandomSource` | `internal/pool` 的 `randInt64N` 注入点 |
| 前端 | 无 DOM mock；只断言可独立求值的纯函数 | `frontend_test.go:186-260` |

**不访问外网**：唯一例外是 smoke 用例打本机临时端口（`internal/panel/credit_upgrade_test.go:858`）。生产代码显式拒绝 nil client 回落到 `http.DefaultClient`（`internal/upstream/modelsdev.go:212-219`）——这条约束保证测试不会意外打真实上游。

## 门控式 skip（必须遵守）

测试环境不满足时**skip 而非 fail**：

| 条件 | 行为 | 位置 |
|---|---|---|
| 无 `node` | 跳过前端/JS 断言 | `panel/frontend_test.go:26,74`、`import_format_test.go:179`、`login_poll_test.go:22` |
| 非 POSIX / 以 root 运行 | 跳过权限相关断言 | `auth/permhint_test.go:13-18`、`credithist/fault_test.go:61-66,411-413` |
| `testing.Short()` / 缺外部源码 | 跳过升级路径用例 | `panel/credit_upgrade_test.go:904-916`（需 `WB2API_UPGRADE_OLD_SRC`） |

写新测试时若依赖环境能力（node/权限/网络），必须用同样的门控，否则 CI 与本地结果会不一致。

## 配置一致性守卫（值得复制的模式）

`cmd/server/config_example_test.go:11-39`：断言仓库根的 `config.example.json` 是合法 JSON、能解析成 `Config`、且新增键在示例里可见。

**来由**（测试注释原文）：PR #55 加 `features.sanitize_brand_scope` 时漏了上一行的逗号，文件变成非法 JSON 而 CI 全绿——因为它只在运行时被 `cp config.example.json config.json` 的人读到，报错现场离提交很远。这个测试把现场挪回 CI。

同类守卫：`config_test.go`（默认值/校验）、`config_save_test.go`（面板保存管线）、`config_env_test.go`（env 覆盖与托管字段）。

## 覆盖率要求

**没有覆盖率门槛**，CI 不跑 `-cover`。事实上的覆盖策略是"每个 bug 修完补一个端到端钉死的用例"：

| 提交 | 钉死的语义 |
|---|---|
| `320bedd` | OAuth 登录的号落池即暂停选号（端到端） |
| `66908b3` | 新增账号默认暂停选号，且「解冻」清不掉 |
| `1a197e3`/`4251777` | 导入接受多种 JSON 形状 |
| `e2d0ded` | 模型未调工具的正常收尾不算错误 |

新增测试时按这个模式：**一个测试钉一个可观察行为**，命名写清业务语义（中文注释说明"钉死什么"）。

## 面板前端的测试方式

`internal/panel/frontend_test.go` 通过 node 执行 `app.js` 片段：

1. **语法检查 + 顶层求值**（`:20-40`）：整份脚本能被 node 解析并求值不抛异常（要求 `app.js` 顶层无 DOM 依赖）。
2. **纯函数断言**（`:58-130`、`:186-260`）：转义、格式化、归属判断等。
3. **渲染契约**（`:262-300`）：任务中心空态与归属标志。

因此改 `app.js` 的硬约束：**纯函数不得依赖 DOM 全局**，否则测试要么失败要么被 skip 掉。
